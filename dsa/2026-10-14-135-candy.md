# DSA Interview Walkthrough — LeetCode 135: Candy

**Difficulty:** Hard  
**Pattern:** Greedy · Two Passes · Local Constraints · Minimal Feasible Assignment  
**Core lesson:** When each element must satisfy constraints relative to both neighbors, solve one direction first, then sweep back to enforce the other without undoing the first. The minimum valid assignment is the maximum of the two directional requirements.

## 1. Interviewer: Problem statement

There are `n` children standing in a line. Each child has a rating. Every child must receive at least one candy. A child with a higher rating than an immediate neighbor must receive more candies than that neighbor. Return the minimum total candies.

```text
ratings = [1, 0, 2]
candies = [2, 1, 2]
answer = 5
```

Equal ratings impose no relative candy requirement; only immediate neighbors matter.

## 2. Recognize the pattern

This is a minimum assignment problem under local inequalities.

For adjacent children:

```text
ratings[i] < ratings[i+1] => candy[i] < candy[i+1]
ratings[i] > ratings[i+1] => candy[i] > candy[i+1]
ratings[i] = ratings[i+1] => no constraint
```

A one-directional greedy pass is not enough because a child can be constrained by both its left and right neighbors.

## 3. Brute force: try assignments

```python
def brute(ratings):
    n = len(ratings)
    best = float("inf")
    chosen = []

    def dfs(i, total):
        nonlocal best

        if total >= best:
            return
        if i == n:
            best = total
            return

        for c in range(1, n + 1):
            if i:
                if ratings[i] > ratings[i - 1] and c <= chosen[-1]:
                    continue
                if ratings[i] < ratings[i - 1] and c >= chosen[-1]:
                    continue

            chosen.append(c)
            dfs(i + 1, total + c)
            chosen.pop()

    dfs(0, 0)
    return best
```

**Time:** exponential; a loose bound is O(n^n).  
**Auxiliary space:** O(n).

## 4. First improvement: repeatedly repair violations

Start everyone at one candy. Repeatedly scan neighboring pairs and raise a higher-rated child if necessary.

```python
def repair(ratings):
    n = len(ratings)
    candy = [1] * n
    changed = True

    while changed:
        changed = False

        for i in range(n - 1):
            if ratings[i] < ratings[i + 1] and candy[i + 1] <= candy[i]:
                candy[i + 1] = candy[i] + 1
                changed = True
            elif ratings[i] > ratings[i + 1] and candy[i] <= candy[i + 1]:
                candy[i] = candy[i + 1] + 1
                changed = True

    return sum(candy)
```

**Time:** O(n^2) worst case.  
**Auxiliary space:** O(n).

The repeated scans happen because constraints propagate in opposite directions.

## 5. Optimal greedy: two passes

First enforce constraints from the left:

```python
candies = [1] * n

for i in range(1, n):
    if ratings[i] > ratings[i - 1]:
        candies[i] = candies[i - 1] + 1
```

Then enforce constraints from the right:

```python
for i in range(n - 2, -1, -1):
    if ratings[i] > ratings[i + 1]:
        candies[i] = max(candies[i], candies[i + 1] + 1)
```

The `max` is crucial: a child may already need many candies because of the left side, and the right pass must not destroy that requirement.

## 6. Dry run

```text
ratings = [1, 2, 2, 1, 0]
```

Start:

```text
candies = [1, 1, 1, 1, 1]
```

Left-to-right:

```text
ratings: 1  2  2  1  0
candies: 1  2  1  1  1
```

Right-to-left:

```text
ratings: 1  2  2  1  0
candies: 1  2  3  2  1
```

Answer = 9.

Equal ratings at indices 1 and 2 do not require equal candies. Index 2 needs three candies because of the descending chain to its right.

## 7. Clean final LeetCode solution — Python

```python
class Solution:
    def candy(self, ratings: list[int]) -> int:
        n = len(ratings)
        candies = [1] * n

        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                candies[i] = candies[i - 1] + 1

        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1]:
                candies[i] = max(candies[i], candies[i + 1] + 1)

        return sum(candies)
```

No lambda functions are used, and the input is not modified.

## 8. Complexity analysis

Two linear passes plus the final sum.

**Time:** O(n).  
**Auxiliary space:** O(n).

An O(1)-extra-space slope-counting solution exists, but the two-pass version is usually the best interview solution because it is simpler and easier to prove.

## 9. Why the greedy solution is optimal

Let `L[i]` be the minimum candies required by increasing constraints coming from the left, and `R[i]` the minimum required by decreasing constraints coming from the right.

Any valid assignment must satisfy:

```text
candies[i] >= max(L[i], R[i])
```

The two-pass algorithm assigns exactly that pointwise lower bound. Rising pairs are satisfied by the left requirement; falling pairs by the right requirement; equal ratings impose nothing.

Since no valid solution can give any child fewer candies than this lower bound, the total sum is minimal.

## 10. Edge cases and common mistakes

- One child -> 1 candy.
- All equal -> one candy each.
- Strictly increasing -> 1,2,3,...
- Strictly decreasing -> ...,3,2,1.
- Valley such as `[3,1,3]`.
- Peak such as `[1,3,1]`.

Common mistakes:
- Doing only the left-to-right pass.
- Overwriting instead of taking `max` in the right-to-left pass.
- Treating equal ratings as requiring equal candies.
- Sorting children by rating and losing adjacency information.

## 11. Interviewer-style follow-up questions

**Why not sort by rating?**  
The constraints are based on original adjacency, which sorting destroys.

**Why scan right-to-left in the second pass?**  
Descending runs need requirements propagated from their right end toward the left.

**Can we use separate left and right arrays?**  
Yes. Compute both directional requirements and sum their pointwise maximum.

**Is there an O(1)-space solution?**  
Yes, using lengths of increasing and decreasing slopes, but it is more delicate around peaks and equal ratings.

**What if ratings are negative?**  
Nothing changes; only comparisons matter.

## 12. What to say aloud

> “This is a local inequality problem with constraints coming from both sides. Brute-force assignment is exponential, and repeated repair can be quadratic. I start everyone at one candy, sweep left-to-right to satisfy rising pairs, then right-to-left to satisfy falling pairs. I use max in the second pass so I preserve any stronger requirement created by the first. Each child gets exactly the maximum of its left and right lower bounds, so the assignment is minimal. The solution is O(n) time and O(n) space.”

## 13. Pattern takeaway

```text
Minimum assignment under neighbor inequalities
                 ↓
Start with one each
                 ↓
Left-to-right satisfies rising pairs
                 ↓
Right-to-left satisfies falling pairs
                 ↓
Use max to preserve earlier requirements
                 ↓
O(n) time, O(n) space
```
