# DSA Interview Walkthrough — LeetCode 51: N-Queens

**Difficulty:** Hard  
**Pattern:** Backtracking · Constraint Tracking  
**Core lesson:** Build the board row by row. At each row, only place a queen in columns and diagonals that are still free, then undo the choice when backtracking.

## 1. Interviewer prompt

Place `n` queens on an `n x n` chessboard so that no two queens attack each other. Return all distinct valid boards.

```text
n = 4
```

There are two valid solutions.

## 2. Recognize the pattern

This is a classic combinatorial search problem with strong local constraints:
- one queen per row,
- one queen per column,
- no two queens on the same diagonal.

That strongly suggests backtracking with pruning.

Placing exactly one queen per row removes the need to track row conflicts. We only track columns and diagonals.

## 3. Brute force

A naive search could choose any `n` cells from `n^2`, then validate the board. That explores an enormous search space.

A better brute-force baseline places one queen in each row, giving up to `n^n` assignments before pruning.

Backtracking rejects invalid partial boards immediately.

## 4. Diagonal representation

For cell `(r,c)`:

- main diagonal identifier: `r - c`
- anti-diagonal identifier: `r + c`

All cells on the same diagonal share the same identifier.

Maintain three sets:
- `cols`
- `diag1` for `r-c`
- `diag2` for `r+c`

## 5. Backtracking state

At row `r`, try every column `c`.

If any constraint set already contains the column or diagonal, skip it.

Otherwise:
1. place `Q`,
2. add the three constraints,
3. recurse to row `r+1`,
4. undo everything.

When `r == n`, a complete valid board has been built.

## 6. Clean final Python solution

```python
class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        board = [["."] * n for _ in range(n)]
        cols = set()
        diag1 = set()
        diag2 = set()
        ans = []

        def backtrack(r):
            if r == n:
                ans.append(["".join(row) for row in board])
                return

            for c in range(n):
                if c in cols or r - c in diag1 or r + c in diag2:
                    continue

                cols.add(c)
                diag1.add(r - c)
                diag2.add(r + c)
                board[r][c] = "Q"

                backtrack(r + 1)

                board[r][c] = "."
                cols.remove(c)
                diag1.remove(r - c)
                diag2.remove(r + c)

        backtrack(0)
        return ans
```

No lambda functions are used.

## 7. Complexity

A useful upper bound is `O(n!)` search states because each row uses a different column, with additional diagonal pruning reducing the actual search. Constructing each output board costs `O(n^2)`.

Auxiliary search state is `O(n)` beyond the output and board representation.

## 8. Correctness

The algorithm places exactly one queen per row. Constraint sets prevent any repeated column or diagonal, so every completed board is valid. Conversely, every valid N-Queens arrangement chooses one legal column in each row; backtracking tries every legal choice, so every valid arrangement is eventually generated.

## 9. Edge cases and common mistakes

- `n = 1` -> one solution.
- `n = 2` or `n = 3` -> no solutions.

Common mistakes:
- using the wrong diagonal formulas,
- forgetting to remove constraints during backtracking,
- storing the mutable board directly in the answer instead of copying/stringifying it,
- scanning the whole board to validate every placement instead of maintaining sets.

## 10. Interviewer follow-ups

**Count solutions only?** Use the same recursion but increment a counter instead of building boards (LeetCode 52).

**Can sets be replaced?** Yes. Boolean arrays or bitmasks are faster and avoid hashing.

**Why row by row?** It removes one constraint dimension automatically and keeps the branching structure simple.

**Bitmask version?** Track occupied columns and diagonals as integer bitsets for high-performance search.

## 11. What to say aloud

> “This is backtracking with constraints. I place one queen per row, so row conflicts disappear. I maintain sets for occupied columns and the two diagonal identifiers r-c and r+c. For each row I try only safe columns, recurse, then undo the placement. Because invalid partial boards are pruned immediately, the search is far smaller than enumerating complete boards and validating afterward.”

## 12. Pattern takeaway

```text
Combinatorial placement
        ↓
Build partial solution incrementally
        ↓
Track constraints explicitly
        ↓
Reject invalid choices immediately
        ↓
Choose -> recurse -> undo
```
