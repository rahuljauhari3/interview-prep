# DSA Interview Walkthrough — LeetCode 322: Coin Change

**Difficulty:** Medium  
**Pattern:** Dynamic Programming · Unbounded Knapsack

## Problem
Given coin denominations and an amount, return the minimum number of coins needed to make that amount, or `-1` if impossible. Each denomination may be used unlimited times.

## Recognition
The same remaining amount appears through many different coin choices, so brute-force recursion repeats subproblems. Unlimited reuse means this is an **unbounded knapsack** style DP.

## Brute force
Try every coin at every remaining amount. Without memoization the search is exponential.

## DP state
Let:

```text
dp[x] = minimum coins needed to make amount x
```

Base case:

```text
dp[0] = 0
```

Transition:

```text
dp[x] = min(dp[x], 1 + dp[x - coin])
```

for every `coin <= x`.

Use `amount + 1` as an impossible sentinel because no valid answer can need more than `amount` coins when denomination 1 exists.

## Clean final Python solution

```python
class Solution:
    def coinChange(self, coins: list[int], amount: int) -> int:
        dp = [amount + 1] * (amount + 1)
        dp[0] = 0

        for current in range(1, amount + 1):
            for coin in coins:
                if coin <= current:
                    dp[current] = min(
                        dp[current],
                        1 + dp[current - coin]
                    )

        return -1 if dp[amount] == amount + 1 else dp[amount]
```

No lambda functions are used.

## Example
For `coins=[1,2,5]`, `amount=11`:
- `dp[1]=1`
- `dp[2]=1`
- ...
- `dp[10]=2` using `5+5`
- `dp[11]=3` using `5+5+1`

## Complexity
- Time: `O(amount * number_of_coins)`.
- Space: `O(amount)`.

## Correctness
Any optimal solution for amount `x` ends with some coin `c`. Before that final coin, the solution must optimally make `x-c`; otherwise replacing it with a better solution would improve the total. The transition considers every possible final coin and therefore finds the optimum.

## Common mistakes
- Using greedy for arbitrary denominations. Example: `[1,3,4]`, amount 6; greedy gives `4+1+1`, optimal is `3+3`.
- Forgetting `dp[0]=0`.
- Returning the sentinel instead of `-1`.
- Confusing minimum-coin DP with number-of-ways Coin Change II.

## Interview follow-ups
- Need number of combinations? Use counting DP instead of minimum DP.
- Each coin usable once? That becomes 0/1 knapsack; iteration direction changes.
- Return the actual coins? Store the chosen predecessor coin for each amount.

## What to say aloud
> “The brute-force recursion repeats the same remaining amounts. I define dp[x] as the minimum coins to form x. For each amount I try every coin as the final coin and transition from dp[x-coin]. Because denominations are reusable, this is unbounded knapsack. The solution is O(amount * coins) time and O(amount) space.”

## Pattern takeaway
```text
Repeated amount subproblems + unlimited item reuse -> unbounded knapsack DP
```
